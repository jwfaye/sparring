# Visual identity and README

## Intent
Give Sparring a brand mark, a favicon and a README that a reader arriving from GitHub understands in one screen:
what the tool is, what it looks like, how to start it. It exists because the page had no icon, the top bar was a bare
word, and the README opened on a wall of commands.

## Context
The mark is a split disc: two half-discs offset vertically, two gloves touching, drawn by hand as a single SVG path
with `currentColor` so it follows the theme tokens. It is inlined in the `.brand` heading of `app/index.html`
(shared: SP-WEB-ASSETS owns the file and its third-party asset tags, which are untouched) and shipped as
`app/img/favicon.svg` (a `prefers-color-scheme` rule picks the fill), `app/img/favicon-32.png` and
`app/img/apple-touch-icon.png`, referenced by `<link rel="icon">` and `<link rel="apple-touch-icon">` in the head.
`server.py` serves `app/` with `http.server.SimpleHTTPRequestHandler`, whose content types come from `mimetypes`
(`image/svg+xml`, `image/png`), and its `img-src 'self' data:` policy already allows same-origin images, so the
server is unchanged. `docs/img/` holds the source mark (`logo.svg`, `logo.png` at 512 px), the README banner in a
light and a dark variant (WebP, transparent background, `<picture>` with `prefers-color-scheme`) and the screenshots
of the three views in both themes, taken with Playwright on `?profile=test` against a server whose grader is
offline. `app/css/style.css` (frontier) gains one rule aligning the mark with the name. `tests/test_brand.py`
checks the favicon links, the served content types, the image sizes and the README references. Code-only:
`resources: []`.

## Goals
- G1: a geometric monochrome mark that reads at 16 px and at 512 px, with no text in it, drawn as SVG with
  `currentColor` so the app does not depend on a raster.
- G2: the page declares an SVG favicon with a PNG fallback and a touch icon, served by `server.py` with the right
  content type and allowed by its Content-Security-Policy.
- G3: a 1600x500 banner with the mark and the name, understated, readable on GitHub's light and dark backgrounds.
- G4: real screenshots of the exercises, quiz and interview views in both themes, each image under 400 KB.
- G5: the README opens with the banner, a tagline, the CI and license badges, a short "What it is" with the three
  modes and the screenshots, then a Quick start, then the existing sections kept accurate; no path, variable,
  config key or command that was only in the README is lost, and the `#development` and `#contributing` anchors
  that `CONTRIBUTING.md` links to still exist.

## Non-Goals
- NG1: a raster logo generated by a model: the Nano Banana image service answered with a quota error, so every image
  is drawn as SVG and rendered with headless Chromium.
- NG2: a restyling of the page: the only visible change in the app is the mark next to the name and the tab icon.
- NG3: a web manifest or a maskable icon set.
- NG4: vendoring the fonts: the banner is rendered once with Inter from Google Fonts and committed as an image.

## Assumptions
- A1: GitHub renders `<picture>` with `prefers-color-scheme` sources in README files and serves WebP images.
- A2: `mimetypes` of Python 3.12 and later maps `.svg` to `image/svg+xml` and `.png` to `image/png`.
- A3: the browsers that run the app support SVG favicons with an embedded `<style>`; the PNG fallback covers the
  others.

## Interface
Inputs:
- `app/index.html`: `<link rel="icon" href="img/favicon.svg" type="image/svg+xml" sizes="any">`,
  `<link rel="icon" href="img/favicon-32.png" type="image/png" sizes="32x32">`,
  `<link rel="apple-touch-icon" href="img/apple-touch-icon.png">`, and the inline `<svg class="mark">` in
  `h1.brand`, `aria-hidden="true"`.
- `docs/img/`: `logo.svg`, `logo.png`, `banner-light.webp`, `banner-dark.webp`, `exercises-{light,dark}.webp`,
  `quiz-{light,dark}.webp`, `interview-{light,dark}.webp`.

Outputs:
- `GET /img/favicon.svg` -> 200, `Content-Type: image/svg+xml`; `GET /img/favicon-32.png` -> 200, `image/png`.

Errors:
- A missing icon file or a wrong content type fails `tests/test_brand.py`; an image over 400 KB fails it too.

## Behavior
### Nominal
1. The browser reads the icon links, picks the SVG when it supports it (its `prefers-color-scheme` rule flips the
   fill in a dark browser chrome), else the 32 px PNG.
2. The top bar shows the mark at 18 px next to "Sparring", in `currentColor`, so it follows the theme.
3. GitHub shows the light banner and screenshots to light-theme readers, the dark variants to dark-theme readers.

### Edge cases
- A browser without SVG favicon support -> the PNG fallback.
- A Markdown renderer without `<picture>` support -> the `<img>` fallback inside it, the light variant.

### Failure scenarios
- `server.py` stops serving `app/img/` (directory moved, wheel mapping changed) -> the favicon request fails; the
  live-server test fails with the status code.

## Architecture Impact
- Adds dependency: SP-BRAND -> SP-WEB-ASSETS (the icon links and the inline mark live in `app/index.html`, which
  SP-WEB-ASSETS owns; its third-party asset tags are untouched).
- New / changed coupling, cycles, or shared state: none.
